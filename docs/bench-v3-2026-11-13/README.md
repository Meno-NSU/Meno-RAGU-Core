# RAGU на новых вопросах бенчмарка v3: где проигрывает Менону 1.1 и почему

1338 новых вопросов бенчмарка (Meno-QA-Benchmark, ветка feat/bench-v3-eval-subset, 109 исключены с причинами), 608 из них с эталонным ответом. Ответы — gemma-4-12B-it; судья — qwen3.8-27b на Everest, RAGAS 0.3.1; среднее и 95% бутстрэп-интервал. Все времена — UTC, 13.11.2026.

## 1. Исходные цифры (до исправлений)

| Пайплайн | Answer correctness | Factual correctness | Faithfulness | Context recall | Answer relevancy | Золото в контексте |
|---|---:|---:|---:|---:|---:|---:|
| Менон 1.1 | 0.512 | 0.352 | 0.774 | 0.437 | 0.545 | 78.3% |
| RAGU v4k | 0.494 | 0.334 | 0.900 | 0.448 | 0.563 | 74.7% |
| RAGU v5k | 0.492 | 0.319 | 0.892 | 0.448 | 0.569 | 74.3% |
| RAGU v5k без LLM-реранкера | 0.488 | 0.325 | 0.884 | 0.418 | 0.556 | ~68% |

RAGU v5k − Менон 1.1: answer correctness −0.022 [−0.038; −0.005], faithfulness +0.115, answer relevancy +0.024. Проигрыш сосредоточен в трёх категориях: многоходовые диалоги (−0.145, 49 вопросов), вопросы о самом диалоге (−0.156, 17), вопросы, зависящие от даты (−0.154, 14); на сложных и общих вопросах RAGU выигрывает (+0.072, +0.069).

**Поправка к метрике «золото в контексте».** В первом отчёте у RAGU стояло 70.3% (v5k) и 71.3% (v4k). Эти числа занижены: страницы контекста RAGU собирались из построчной атрибуции, и строки сводных документов из нескольких страниц (карточки направлений и т. п.) без собственной ссылки не давали ни одного URL, а у Менона каждый документ контекста засчитывается по своей основной ссылке. При одинаковом счёте (документ контекста засчитывается по своим ссылкам) — числа в таблице выше. Пример: doc-b6-015, «288 000 руб. … приказ 1411-3» был в контексте RAGU на первом месте, но не засчитывался.

## 2. Диалоги и даты

65 крупных проигрышей разобраны по ответам. Механизмы:

- реплики пользователя без ответа выпадали из истории (в бенчмарке 402 из 444 историй — только реплики пользователя);
- ответы ассистента в истории обрезались до 9 слов;
- старый переписчик запроса терял тему («А какого числа?» → День числа Пи);
- в контексте RAGU не было дат документов, поэтому прошедшие события подавались как текущие.

Исправления (Meno-RAGU-Core):

- `feat/dialogue-memory` (e1ba7bd): память диалога и анализ реплики из Менона 1.1 — недавние реплики целиком в бюджете 5000 токенов, старые — в сводке; один вызов даёт маршрут, самостоятельный вопрос и подзапросы; правило о датах в промпте ответа.
- `fix/engine-cross-encoder-scores` (fdc28ff): даты документов в контексте, как у Менона («**Дата документа:** 13.10.2026»). Корпус стенда дат не содержал; они берутся из метаданных чанков KB v3.8 по `kb_doc_id` в файл `document_dates.json` стенда: датированы 105 818 из 171 774 документов KB (посты 80%, новости 45%, публикации 100%); у документов не из KB (преподаватели, база nsu-v1, карточки программ) дат нет.

## 3. Почему нужные документы не попадали в контекст

Трассировка всего конвейера RAGU на 89 вопросах, где золотой страницы не было в контексте v5k:

| Где теряется | Вопросов |
|---|---:|
| документа нет в корпусе стенда | 10 |
| не попал ни в один пул поиска (ни граф, ни BM25+dense) | 20 |
| в пуле, но за пределами 40 кандидатов на LLM-проверку (места ~36–50) | 19 |
| LLM оценил, но в контекст не взяли (у 6 оценка ≈1.0) | 17 |
| был в контексте, ошибка метрики (см. поправку выше) | 10 |
| исправлено новым диалоговым кодом | 11 |
| ошибки прогона | 2 |

У 61 из 89 золотой документ есть в графе, у 18 — только в индексе чанков.

**Смешанные шкалы при объединении каналов.** Движок прогоняет через один кросс-энкодер (bge-reranker-v2-m3) и чанки графового канала, и чанки канала BM25+dense, но у графового канала сохранял только порядок: его чанки получали 1/(место+1), нормированное на ~200 кандидатов, а канал чанков — свои 30 оценок, нормированные на 30. Сущности шли по расстоянию эмбеддингов, связи — по месту. В итоге графовый чанк с 8-го места и ниже оказывался ниже всех результатов канала чанков, а графовые элементы занимали в среднем 18.7 из 40 мест на LLM-проверку. Исправление (ce99885): все кандидаты на шкале кросс-энкодера.

Повтор тех же 300 поисков без LLM (`scale_replay.py`):

| | старое объединение | новое |
|---|---:|---:|
| золото среди 40 кандидатов на LLM-проверку | 72.3% | 75.0% (+8, −0) |
| золото в топ-5 чанков | 55.0% | 61.0% |
| графовых элементов среди 40 кандидатов | 18.7 | 5.4 |

Весь конвейер с LLM, те же вопросы (`prep_ab.py`, 139 пар):

| | старое объединение | новое |
|---|---:|---:|
| золото среди кандидатов на LLM-проверку | 74.1% | 77.7% (+5, −0) |
| золото в контексте | 66.2% | 66.2% (+6, −6) |

**Насыщение LLM-проверки.** На вопрос приходится от 23 до 78 кандидатов с оценкой LLM ≥ 0.99 при 12 местах в контексте: проверка «можно ли ответить по документу» работает как фильтр, а не как ранжирование, и кто войдёт, решают 20% оценки движка и априорное качество источника. Новое объединение меняет этот выбор: в контекст вошли некролог Витяева (prod-0038), социальные стипендии (tg-0198), центр трансфера технологий (tg-0211), но ушли другие золотые чанки из канала BM25+dense.

Офлайн-проигрыш правил отбора на сохранённых оценках всех кандидатов (300 вопросов, без судьи): текущее правило 74.0%, 16 мест 75.3%, логарифм шансов LLM + bge + приор 75.7%, не больше двух чанков со страницы 73.7%, фильтр LLM + bge (как у Менона) 63.7%, только bge без LLM 67.3%. Правила отбора дают не больше 1.5 пункта.

**Полнота: что находит один и не находит другой.** На тех же 300 вопросах документный контекст RAGU v5k содержит золото в 74.3%, Менона 1.1 — в 78.3%, их объединение — в 86.3%: 36 вопросов находит только Менон, 24 — только RAGU. В большинстве «только Менон» документ есть в корпусе RAGU, но его поиск по чанкам (bge-m3, один проход 50 → 30) до него не добирается; около 5 — страницы, которые у RAGU есть только в старой версии nsu-v1 (при расширении стенда KB v3.8 не заменяла страницы, уже бывшие в базе).

**Глубина связанных кандидатов графа** (GRAPH_RELATED_CANDIDATES, новое объединение, 300 вопросов, без LLM): 200 — золото среди кандидатов на LLM-проверку 75.0%, поиск p50 5.8 с; 100 — 73.7%, 3.5 с; 50 — 71.7%, 2.3 с. После исправления шкалы глубокий пул графа приносит золото, так что сокращение больше не бесплатно.
