# Причинная проверка `question_first`

Перестановка секций меняет оценки полезности документов и состав графовых справок.
Её нельзя считать оптимизацией, сохраняющей поведение. В четырёх диагностических
примерах обнаружены устойчивое улучшение, устойчивое ухудшение и потеря части
намерения пользователя при переписывании вопроса. Средняя оценка на всём W5
не объясняет эти механизмы и не гарантирует отсутствие регрессий.

## Что проверено

Сначала сопоставлены сохранённые ответы W5 на 1454 вопросах. Точные контексты
совпали в 18 парах, поисковые запросы — в 1333, воспроизведённая история — в 1448.
Полные записи контекстов вместе с идентификаторами и метаданными совпали в 15 парах.
На 29 вопросах профиля `robustness` Qwen отметил пять ухудшений без улучшений;
GPT-OSS по некоторым из этих примеров дал противоположное направление изменения.
Метки судей проверялись по тексту ответа и источникам, а не принимались за эталон.
Числа и выбранные примеры — в [w5_summary.json](w5_summary.json).

Ограничение исторического судейства: фактический запуск W5 передавал судье
до 40000 символов; все контексты обоих вариантов помещались целиком
(максимумы 33085 и 34469). Ни прежний лимит 12000, ни обрезка графовых справок
не объясняют эти результаты. Однако построитель судейских задач сохранял
последние шесть реплик по 500 символов и брал историю из исходного задания.
В обоих вариантах это изменило восемь историй из 1454; с учётом фактически
воспроизведённых предыдущих ответов история судьи отличалась от входа конвейера
в 14 случаях. В профиле robustness изменены пять историй из 29, но ни одна из них не входит
в пять ухудшений Qwen. Эти ухудшения обрезкой истории не объясняются.
Сжатый текст памяти, который видел сам генератор W5, полностью не восстанавливается
из этих записей. Следовательно, исторические оценки диалога требуют повторения
с точной историей задания и отдельно с фактической памятью генератора.
Это ограничение не отменяет новых причинных опытов с зафиксированными входами.
Агрегаты без диалогов — [judge_history_audit.json](judge_history_audit.json).

Для новой проверки выбраны четыре публичных диагностических примера: неоднозначная
справка, программы преподавателя, базовый институт кафедры и устойчивый факт
из раздела «Руководство». Это намеренная выборка для выяснения причин,
а не оценка среднего качества продукта.

Из исходного захвата взяты полные множества кандидатов: 69, 78, 64 и 70,
всего 281. Кандидаты, история и содержимое секций зафиксированы. Проверены порядки:

- `L`: словарь, документ, история, вопрос, инструкция;
- `Q`: история, вопрос, инструкция, словарь, документ;
- `QI`: история, вопрос, словарь, документ, инструкция.

Пустые секции пропускались. Контрольные суммы подтверждают побайтовую неизменность
содержимого каждой секции. Каждый вариант повторён с `seed=42/43`, температура 0.
Дополнительно проверены `SL/SQ`: те же `L/Q` с `structured_outputs.choice`
и исправленным суммированием вероятностей разных токенов, декодируемых одной цифрой.
Эта проверка протокола учитывается отдельно от перестановки секций.

Генератор получил сохранённые контексты `L/Q`, исходную историю и зафиксированную
системную дату. Исходный запрос генерации `L` восстановлен штатной функцией
побайтово во всех четырёх примерах. Параметры: температура 0,1, `seed=42/43`,
`max_tokens=8192`. Контексты по новым оценкам `QI` не собирались.

Выполнено 2810 однотокенных запросов и 16 генераций, ошибок нет. Продолжительность
62,73 с относится к прогретому диагностическому запуску; это не замер задержки
полного поиска. Результаты — [focus_aggregate.json](focus_aggregate.json),
дополнительная проверка — [focus_diagnostics.json](focus_diagnostics.json).

## Оценки меняются сильнее, чем при повторе

| Пример | Изменившиеся метки `L→Q`, первый повтор | Совпадение первых 16 по оценке реранкера | Среднее абсолютное изменение оценки |
|---|---:|---:|---:|
| Неоднозначная справка | 3/69 | 13/16 | 0,029 |
| Программы Карпова | 9/78 | 12/16 | 0,077 |
| «Вектор» | 8/64 | 12/16 | 0,122 |
| «Руководство» | 11/70 | 12/16 | 0,141 |

Итого изменились 31/281 меток, или 11,0%. При повторе одного порядка первые 16
совпали во всех примерах; среднее абсолютное изменение оценки не превышало
0,000074. Следовательно, эффект перестановки существенно больше наблюдавшегося
численного шума. Здесь ранжирование считается только по оценке реранкера:
производственный отбор также учитывает поисковую оценку и приоритет источника.

Исправленные `SL/SQ` сохранили первые 16 своего исторического аналога во всех
примерах и повторах; из 1124 пар меток отличается одна возле границы решения.
Значит, обнаруженный эффект порядка не объясняется старым полем `guided_choice`
или ошибкой обработки повторяющихся цифровых токенов. Эти ошибки совместимости
требуют отдельного исправления, но не являются установленной причиной W5.

Возврат инструкции в конец (`QI`) не восстанавливает `L` во всех случаях:
совпадения первых 16 составили 13, 13, 13 и 11. Качество новых ответов `QI`
не измерено; выпускать его как готовое исправление по этим данным нельзя.

## Как меняется ответ

| Пример | `L`, два seed | `Q`, два seed | Проверенная причина или граница вывода |
|---|---|---|---|
| «Вторая справка» без перечисления вариантов в истории | Обе процедуры и уточнение 2/2 | Уточнения нет 2/2 | Вопрос остаётся неоднозначным; почти одинаковые документы сами по себе её не разрешают |
| По каким программам Карпов преподаёт физику | Указана «Физика → Лечебное дело» 2/2 | Нужная строка пропущена 2/2 | Правильная таблица есть в обоих контекстах; её фрагмент имеет ранг 1 во всех пяти вариантах |
| Является ли «Вектор» базовым институтом | Ложно сообщает об отсутствии сведений 2/2 | Использует явное указание в документе 2/2 | Нужная фраза присутствует в обоих контекстах |
| Факт из раздела «Руководство» | Верно 2/2 | Верно 2/2 | Меняются подбор документов и подробность ответа |

В примере Карпова `Q` вместо требуемой строки добавляет другую истинную связь:
«Физические основы диагностики → Лечебное дело». Это потеря полноты ответа
и смена предмета перечисления. Само добавленное утверждение подтверждено таблицей;
называть его выдуманным фактом нет оснований. Метка Qwen `contradicts` здесь
строже буквального содержания ответа; `partial` GPT-OSS точнее описывает пропуск.

## Причинная абляция графовых справок

В примере Карпова документы `Q` сохранены побайтово. Менялись только справки
по графу; вопрос, системная дата, параметры генерации и два seed сохранены.

| Справки при документах `Q` | Ответ содержит требуемую «Физика → Лечебное дело» |
|---|---:|
| Исходные `Q` | 0/2 |
| Те же `Q`, общий с `L` порядок | 0/2 |
| Без справок графа | 2/2 |
| Полный набор справок `L` | 2/2 |

Набор `L` содержал отдельную связь преподавателя с физикой; набор `Q` заменил её
связью с математикой и компьютерными науками, сохранив другую дисциплину.
Перестановка тех же справок не помогла. Удаление справок или возврат набора `L`
восстановили требуемую строку. Это локальное причинное подтверждение влияния
выбранного набора графовых сводок на использование правильной таблицы.

В варианте с набором `L` словарь, инструкция, системный промпт и остальные поля
запроса совпали с контролем. Удаление всех справок также меняет штатную инструкцию
об их использовании. Какая отдельная справка вызвала эффект, этим опытом
не установлено. Данные — [qa_ablation_aggregate.json](qa_ablation_aggregate.json).
Восемь генераций, ошибок нет.

## Переписывание теряет часть вопроса

Исходный вопрос о «Векторе» спрашивает одновременно о статусе базовой организации
и о гарантии места практики. Самостоятельный вопрос, переданный реранкеру,
оставляет только гарантию. Это отдельная ошибка до сборки ответа.

На двух фрагментах с прямым указанием базового института и двух отрицательных
контролях проведены 32 однотокенных запроса: два порядка, два вопроса, два seed.
В отрицательных контролях из того же множества кандидатов нет ни «Вектора»,
ни сведений о практике; их роль и причина выбора записаны до генерации.
Штатная сборка промпта подтвердила изменение только `CURRENT QUESTION`.

| Вопрос реранкеру | Два нужных фрагмента | Два отрицательных контроля |
|---|---|---|
| Урезанный | Метка 0 во всех 8 запросах; оценка 0,002–0,007 | Метка 0 |
| Исходный, обе части | Метка 2 во всех 8 запросах; оценка 0,810–0,996 | Метка 0; оценка ≤0,000168 |

Следовательно, сохранение исходного намерения восстанавливает полезность нужных
фрагментов независимо от `L/Q`. Это ещё не проверка качества полного поиска
при новом общем правиле переписывания. Результат —
[rewrite_ablation_aggregate.json](rewrite_ablation_aggregate.json), ошибок нет.

## Что исправлять дальше

1. Проверять сохранение всех частей вопроса при его превращении в самостоятельный.
   Сопоставить переранжирование по исходному вопросу с историей и по переписанному
   на отдельной выборке, включая многошаговые диалоги.
2. Сохранять в справках совместные связи таблицы: преподаватель, конкретная
   дисциплина и программа. Набор отдельных пар не гарантирует восстановления
   нужного отношения при генерации. Проверять сводки по точной исходной строке.
3. Измерять отдельно полноту найденных фактов, их использование в ответе,
   разрешение неоднозначности и ошибки судьи. Общая оценка скрывает разные причины.
4. Оставлять `question_first` экспериментальным до проверки заранее определённых
   критериев на независимой выборке. Возврат инструкции в конец также требует
   полного опыта с поиском и генерацией.

Эти опыты устанавливают локальные механизмы и воспроизводимость двух seed.
Они не доказывают средний ущерб `Q`, преимущество отказа от графа или готовность
какого-либо нового промпта к выпуску.

## Воспроизведение

Исходные запросы, ответы и полные контексты остаются на сервере. В этом каталоге
нет массивов пользовательских диалогов, payload-файлов или учётных данных.
Нужны исходные артефакты `rel1119b`/`judge1119`, зафиксированный словарь, среда
проекта с `httpx`/NLTK и `PYTHONPATH`, содержащим `src` и `code` той же версии.

Переменные примеров: `AUDIT_BASE_DIR` — каталог с исходными экспериментами,
`AUDIT_DIR` — отдельный рабочий каталог, `ABBR_PATH` — словарь,
`MODEL_BASE_URL` — проверяемый OpenAI-совместимый адрес Gemma с суффиксом `/v1`.

```bash
python prepare_focus.py --base-dir "$AUDIT_BASE_DIR" --out-dir "$AUDIT_DIR"
python run_focus.py --payload "$AUDIT_DIR/focus_payloads.json" \
  --abbr "$ABBR_PATH" --base-url "$MODEL_BASE_URL" --out "$AUDIT_DIR/run" \
  --gate "$AUDIT_DIR/start" --structured --prepare-only
python prepare_qa_ablation.py --dir "$AUDIT_DIR" --abbr "$ABBR_PATH"
python run_rewrite_ablation.py --dir "$AUDIT_DIR" --indices 12,18,27,56 \
  --abbr "$ABBR_PATH" --base-url "$MODEL_BASE_URL" \
  --gate "$AUDIT_DIR/rewrite-start" --prepare-only
```

Подготовительные команды не вызывают модель. Для согласованного повторения
основного опыта уберите `--prepare-only`; процесс ожидает появления файла
`--gate`, затем проверяет модель через `/models`. Для восьми генераций абляции:

```bash
python run_qa_ablation.py --dir "$AUDIT_DIR" --base-url "$MODEL_BASE_URL" \
  --gate "$AUDIT_DIR/qa-start"
python analyze_focus.py --dir "$AUDIT_DIR"
python scan_w5.py --base-dir "$AUDIT_BASE_DIR"
```

Каждый опыт имеет отдельный файл запуска. Индексы 12, 18, 27 и 56 относятся
именно к сохранённому множеству кандидатов этого опыта; их контрольные суммы
приведены в агрегате. Скрипты не загружают граф и не перезапускают службы.
Основной опыт ограничен 900 с и останавливает отправку ожидающих запросов
после трёх ошибок. Полные ответы сохраняются только в рабочем каталоге;
публикуются числовые агрегаты и необходимые короткие фрагменты публичных примеров.
