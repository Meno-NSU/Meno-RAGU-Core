# Кеш токенов для словаря сокращений

Кеш сохраняет наборы обычных и стеммированных токенов документов и общей части
вопроса с историей. Ключ — полный фактический текст фрагмента; новые варианты
вопроса или истории получают отдельные записи. Объединение наборов выбирает
те же сокращения, что обработка исходной строки с двумя переводами строки
между частями. Форматирование каждый раз читает текущие ключи и расшифровки
словаря. Готовые словарные блоки и ответы модели не кешируются.

Кеш принадлежит одному `StandResources` и его стеммеру. Наборы токенов неизменяемы;
доступ к LRU защищён блокировкой. Записи появляются по мере обращения, без
предварительной обработки корпуса. Ограничения: 2048 записей и 64 МиБ учтённого
размера ключей, наборов, строк токенов и служебных элементов. Слишком большая
запись обрабатывается без сохранения. Изменение словаря не требует очистки кеша.

CPU-проверка использовала существующие P1-запросы, NLTK 3.9.4 и razdel 0.5.0.
К модельным HTTP-сервисам она не обращалась; CUDA была отключена. Исходные
запросы оставались на сервере, опубликованы только агрегаты и хеши исходников.

| Проверка | Без кеша | Первый проход с кешем | Совпадение полных сообщений |
|---|---:|---:|---:|
| 50 запросов выбранного пула | 386,63 мс | 366,89 мс | 50/50, оба порядка разделов |
| 281 запрос выбранных пулов | 1686,93 мс | 1558,07 мс | 281/281, оба порядка |
| 10 548 общих уникальных пар P1 A/B | 69,201 с | 56,582 с | 10 548/10 548, оба порядка |

Каждая исходная сборка `legacy` также дословно совпала с сохранёнными сообщениями
P1. Всего проверено 21 096 сравнений кеша с исходной функцией для `legacy` и
`question_first`, без расхождений. Полный проход включал 8980 разных текстов
документов и 100 сочетаний вопроса с историей. В конце кеш содержал 2048 записей,
61 530 112 учтённых байт, 11 362 попадания и 9734 промаха; 7686 записей вытеснены.

В этой последовательности построение сообщений потребовало на 18,2% меньше CPU,
примерно на 126 мс меньше на сочетание вопроса с историей. Это измерение участка
построения запросов, не ускорение ответа RAGU на 18,2%. Искусственно прогретый
повтор первых 50 сообщений занял 1,26 мс; он показывает предел повторного
использования и не описывает новые вопросы в продакшене.

Локальные тесты дополнительно проверяют границы фрагментов, оба вида стеммера,
JSON-ответы, изменение словарных ключей и расшифровок, разные вопросы и истории,
изоляцию ресурсов, параллельный доступ и ограничения памяти.

Воспроизведение на сервере с исходными P1-файлами:

```bash
uv run python docs/abbreviation-cache-2026-11-20/profile_abbreviation_cache.py \
  --abbreviations /path/to/stand/knowledge/abbreviations.json \
  --capture-a /path/to/p1/capture_A.jsonl \
  --capture-b /path/to/p1/capture_B.jsonl \
  --output /path/to/cpu-proof.json
```

`--focus /path/to/focus_payloads.json` проверяет выбранные 281 запрос;
`--limit 50` ограничивает число запросов. Скрипт проверяет полные сообщения в
двух порядках разделов, поэтому его общее время включает дополнительные
проверочные сборки. В таблице приведены отдельные замеры `legacy`.

Хеш выполненного скрипта сохранён в `cpu_results.json`. Публикуемый скрипт
отличается сортировкой импортов и явным захватом значения в синхронном
замыкании; сообщения и измеряемые вызовы сохранены. Хеши четырёх проверенных
модулей совпадают с исходниками этого изменения.
