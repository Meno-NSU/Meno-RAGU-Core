## 1. Слияние поиска (HYBRID_FUSION)

**Что не так.** Каждый гибридный поиск (сущности, связи, фрагменты) сливает плотный список и BM25-список через RRF
Qdrant по умолчанию. RRF считает оба списка одинаково. Поэтому точка на местах (a, b) получает ровно тот же балл, что
точка на местах (b, a), а точка, найденная одним списком, — тот же, что точка на том же месте другого списка. Порядок
таких ничьих произволен.

**Замер без судьи.** `scripts/fusion_sim.py`: 324 вопроса с эталонными страницами из 558, каждый переписан один раз
(gemma). Поиск повторён дважды для каждого варианта на тех же запросах.

| Вариант | Эталон в пуле LLM-реранкера | Выиграл / потерял к rrf#1 | Эталон где-либо в выдаче | Тот же пул при повторе |
|---|---:|---:|---:|---:|
| rrf (сейчас в проде) | 282/324 | — | 295/324 | 209/324 (65%) |
| rrf, k = 60 | 282/324 | 0 / 0 | 295/324 | 218/324 (67%) |
| dbsf | 281/324 | 0 / 1 | 293/324 | 316/324 (97,5%) |

Выводы:

- Повторный одинаковый запрос даёт другой пул кандидатов для 35% вопросов. Значит, ответ на один и тот же вопрос
  меняется от раза к разу без причины.
- k = 60 не помогает: зеркальные места (a, b) и (b, a) равны при любом k.
- DBSF устойчив, но теряет эталон в одном вопросе.
- На полноту поиска ничьи не влияют: rrf#1 и rrf#2 находят эталон в одних и тех же вопросах.

**Правка.** Вариант `rrfw` — тот же RRF с весом BM25-списка 1 − 10⁻⁴. Каждая ничья уходит плотному списку, остальной
порядок не меняется. Это проверяет тест по формуле RRF во float32: ломаются все ничьи первых 100 мест и не меняется
ни один другой порядок первых 20 мест.

**Замер `rrfw`.** Отдельный прогон с контрольным rrf#1 в той же сессии, на тех же переписанных запросах.

| Вариант | Эталон в пуле LLM-реранкера | Выиграл / потерял к rrf#1 | Эталон где-либо в выдаче | Тот же пул при повторе |
|---|---:|---:|---:|---:|
| rrf (сейчас в проде) | 282/324 | — | 295/324 | 209/324 (65%) |
| **rrfw** | **282/324** | **0 / 0** | **295/324** | **319/324 (98,5%)** |

Критерий принятия выполнен: полнота поиска та же, а пул кандидатов повторяется почти всегда. Оставшиеся 5 вопросов
меняются из-за другого шума, не из-за слияния.

**Решение.** Владелец принял `rrfw` по этому замеру, без отдельного прогона судьи. Порядок кандидатов при ничьих был
случайным, его ожидаемое качество не меняется, а ответ на один и тот же вопрос перестаёт меняться от раза к разу.

- main `62909cb`: `HYBRID_FUSION` по умолчанию `rrfw`, CI зелёный.
- `deploy_ragu_v7.sh` на проде привязан к `62909cb` (резервная копия `deploy_ragu_v7.sh.bak-20261118d`).
- Выкатка — владелец: `sudo bash /home/m.kulakov/meno-v2/ragu-probe/deploy_ragu_v7.sh /home/m.kulakov/meno-v2/ragu-v2/stand-v6k2`.

## 2. Контекст без служебных меток (CONTEXT_STYLE=sources)

**Что не так.** В промпте ответа документы пронумерованы («DOCUMENT 12»), есть раздел «ЭЛЕМЕНТЫ ГРАФА ЗНАНИЙ» с
типами онтологии и стрелками связей. Модель повторяет это пользователю: «согласно документу №9», «в графе знаний
указано». Системный промпт это уже запрещает, но не помогает.

Доля ответов v6k2 с такими метками (`scripts/leaks.py`):

| Набор | Ответов | Номер документа или фрагмента | Граф знаний, элемент графа, тип | Любая из меток | «В предоставленных документах» и т. п. |
|---|---:|---:|---:|---:|---:|
| core | 373 | 4,6% | 1,3% | 5,6% | 28,2% |
| набор B | 527 | 10,8% | 4,0% | 12,7% | 17,8% |
| synthetic_kb | 235 | 7,2% | 1,3% | 7,7% | 14,5% |
| дизлайки (переигровка) | 136 | 8,1% | 3,7% | 11,0% | 33,8% |

Последний столбец — это не метки, а оборот «в предоставленных документах». Он идёт из системного промпта Менона 1.1
(«опираясь на документы, переданные вам»). Этот промпт закреплён тестом дословного совпадения, его я не трогаю.

**Правка.** При `CONTEXT_STYLE=sources` каждый документ — это «ИСТОЧНИК» без номера: название, дата, аннотация,
фрагменты без номеров. Каждый элемент графа — справка в разделе «СПРАВКИ ПО МАТЕРИАЛАМ»: имя или два конца связи,
описание, названия документов, на которые она опирается. Вид и тип элемента не показываются. Инструкция называет
разделы без номеров. По умолчанию остаётся `legacy`.

**Замер.** Парный прогон `scripts/ctx_answers.py`: для каждого вопроса этапы до генерации выполняются один раз и
повторяются для второго стиля из кэша. Оба стиля получают одни и те же фрагменты и элементы графа, разница только в
оформлении. Вопросы: core, набор B, synthetic_kb, 136 дизлайков.

Все 1271 пара получены без ошибок. Повтор этапов из кэша точный: ноль промахов кэша, одни и те же фрагменты в
обоих стилях.

Критерий принятия:

- утечки меток заметно падают;
- полнота (vital recall) и противоречия по судье не хуже legacy на тех же вопросах.

**Утечки меток** (`scripts/leaks.py`, парно по вопросам):

| Набор | Пар | legacy | sources | только legacy / только sources / оба |
|---|---:|---:|---:|---:|
| core | 373 | 27 (7,2%) | 2 (0,5%) | 26 / 1 / 1 |
| набор B | 527 | 73 (13,9%) | 8 (1,5%) | 67 / 2 / 6 |
| synthetic_kb | 235 | 20 (8,5%) | 1 (0,4%) | 20 / 1 / 0 |
| дизлайки | 136 | 14 (10,3%) | 0 | 14 / 0 / 0 |
| всего | 1271 | 134 (10,5%) | 11 (0,9%) | 127 / 4 / 7 |

- Номера документов и фрагментов исчезли: 114 → 1. Тот единственный случай — «раздел 14.1 справочника НГУ», то есть
  содержание, а не метка.
- «Граф знаний» и типы исчезли: 34 → 0.
- Оставшиеся 10 случаев называют раздел «справки по материалам».
- Оборот «в предоставленных документах» не изменился: он из закреплённого системного промпта.

**Качество по судье** (qwen3.8-27b, контекст целиком, протокол Meno Eval v1, `tables_sources_vs_legacy`):

| Страта | sources | legacy | Разность, 95% ДИ | Противоречия sources / legacy |
|---|---:|---:|---|---|
| core (взвешенно) | 0,600 | 0,592 | +0,008 [−0,017; +0,033] | 0,281 / 0,296 |
| synthetic_kb | 0,881 | 0,881 | −0,001 [−0,022; +0,021] | 0,089 / 0,098 |
| набор B | 0,804 | 0,810 | −0,007 [−0,020; +0,005] | 0,148 / 0,139 |

Отказы, доля неподтверждённых утверждений и решённые вопросы тоже не различаются.

**Решение.** Принято: `CONTEXT_STYLE` по умолчанию `sources` (main), `legacy` можно выбрать. Тесты, которые
проверяют формулировки legacy, теперь явно просят его. Эталонный снимок записан в legacy и охраняет этот путь. Их
двойники проверяют справки и их документы в новом стиле.

## 3. Проверка утверждений по показанным источникам — не делаю

**Откуда взялась задача.** Судья qwen в бенчмарке 18.11 находит у RAGU больше ответов с «неподтверждёнными
утверждениями», чем у Менона: в core 0,618 против 0,492, в наборе B 0,480 против 0,355.

**Замер сигналов без нового судьи.** `scripts/support_pilot.py` и `scripts/signals.py`. Взяты 333 ответа core с
контекстом, 3707 предложений. 784 предложения сопоставлены с претензиями судьи.

| Сигнал | AUC по предложениям |
|---|---:|
| gemma сама оценивает опору предложения на источники (0/1/2, вероятности из logprobs) | 0,51 |
| лучший балл кросс-энкодера bge-reranker-v2-m3 по фрагментам контекста | 0,38 (обратный) |
| числа, ссылки и почта предложения, которых нет ни в контексте, ни в вопросе | 0,50 |

Ни один сигнал не отличает помеченные судьёй предложения от остальных. Поэтому сначала я проверил сами пометки.

**Почему.** Судья видит только первые 12 000 символов контекста. Так задано в `make_tasks_final.py`
(`ctx_chars`) и `judge_llm.py` (`--max-context`).

| Контекст, переданный судье | Медиана, символов | Обрезано | Скрыто от судьи |
|---|---:|---:|---:|
| Менон 1.1, core | 8 067 | 6 из 326 | 0% |
| Менон 1.1, набор B | 7 907 | 10 из 527 | 0% |
| RAGU v6k2, core | 19 161 | 332 из 333 | 37% |
| RAGU v6k2, набор B | 18 446 | 526 из 527 | 35% |

Элементы графа стоят в конце контекста, так что судья их почти никогда не видит.

- **Пометки опираются на скрытую часть.** У 61% помеченных предложений есть фрагмент контекста, содержащий не меньше
  70% их основ слов. У 68% из них этот фрагмент начинается после 12 000-го символа (`scripts/trunc.py`).
- **Выборочная проверка.** Во всех пяти случайных пометках утверждение есть в контексте, часто дословно: 16-е место
  НГУ в RAEX-100 стоит в аннотации документа 8; варианты дайкири перечислены в посте, хотя судья пишет «нет в
  референсе и контексте» (`scripts/spot.py`).
- **RAGAS подтверждает.** RAGAS получал контекст целиком. Его faithfulness выше у RAGU: v3 0,789 против 0,675,
  набор B 0,934 против 0,821.

Итог: разрыв в «неподтверждённых утверждениях» — в основном артефакт обрезки контекста у судьи. Проверка и
переписывание ответа по таким сигналам не исправили бы реальную проблему, поэтому этот шаг я не делаю.

**Противоречия эталону — отдельная история.** Обрезка контекста их не касается: core 0,287 против 0,208. Проверка
четырёх случаев:

- **Группы 24137 и 23209 — ошибка эталона.** Эталон говорит, что расписания нет в базе знаний. В контексте RAGU
  есть занятия этих групп из записей преподавателей («Пн 12:40 лаб СМВМ … гр.24137»). Эталоны, видимо, писались по
  базе без этих записей.
- **«В. В. Дюбанов» — настоящая ошибка RAGU.** Модель достроила инициалы до «Владимир Владимирович» и назвала его
  сотрудником НГУ.
- **Федорук как ректор — настоящая ошибка RAGU.** В контексте не нашлось сведений 2026 года о новом ректоре. Ответ
  сам оговорил, что данные могут быть устаревшими.

Настоящие ошибки узкие: достройка имён по инициалам, устаревшие факты, частичное расписание, выданное за полное. Это
пункты «время в данных» и «утверждения и тёзки в графе» плана, а не проверка генерации.

**Проверка судьёй с полным контекстом** (18.11, сессия judge1118b, `--max-context` 40 000). Пересужены те же ответы
бенчмарка 18.11 (RAGU v6k2) и 16.11 (Менон 1.1), `scripts/cut_vs_full.py`:

| Ответы | «Есть неподтверждённые утверждения»: судья видел 12 000 символов | весь контекст | Перевернулось 1→0 / 0→1 |
|---|---:|---:|---:|
| RAGU v6k2, v3 | 0,515 | 0,321 | 121 / 3 |
| RAGU v6k2, набор B | 0,480 | 0,324 | 88 / 6 |
| Менон 1.1, v3 | 0,377 | 0,352 | 26 / 11 |
| Менон 1.1, набор B | 0,355 | 0,330 | 14 / 1 |

С полным контекстом в core (взвешенно) у RAGU неподтверждённых утверждений **меньше**, чем у Менона: доля 0,206
против 0,257, разность −0,051 [−0,086; −0,017]. При обрезке было +0,043.

- **Противоречия эталону не изменились.** У RAGU их по-прежнему больше: 0,303 против 0,212. Это настоящая
  оставшаяся разница. Часть её — устаревшие эталоны «нет в базе знаний».
- **Полнота.** Core 0,594 против 0,574, разность не различима. Набор B 0,811 против 0,704, RAGU лучше.

**Что осталось.**

1. **Протокол Meno Eval v1.** Судить с полным контекстом: `ctx_chars` и `--max-context` 40 000.
2. **Эталоны.** Перепроверить эталоны «нет в базе знаний» по самой базе: где сведения есть, эталон устарел.
3. **Противоречия RAGU в core.** Ими займутся пункты плана «время в данных» (устаревшие факты) и «утверждения и тёзки
   в графе» (достройка имён по инициалам, тёзки).
