# AGENTS.md

Guidance for OpenCode sessions working in this repo. The README (in Russian) is the authoritative source of truth; it documents every script, so read it first. **Keep the README current**: whenever a script is added or its CLI/behavior changes, update the README in the same change. New README text must be written in good scientific-technical Russian — see Style notes.

## What this is

Experimental ("стенд") version of **Менон / Meno**, a Russian-language RAG dialog system for NSU (Novosibirsk State University) applicants. Retrieval is RAGU-only: a knowledge graph searched in local (entity-neighborhood) + naive (hybrid dense bge-m3 + sparse fastembed-BM25, fused by reciprocal rank fusion in Qdrant) modes produces a mixed pool of chunks, entities, and relations; a generative LLM (LLM-as-reranker) reranks the pool; the answer is generated from documents plus graph-element blocks. Meno keeps query rewriting and the final rerank/QA stages. Model backends (Meno LLM, bge-m3 embedder, bge-reranker-v2-m3 scorer) are OpenAI-compatible services. Domain text and prompts are Russian.

## Critical: run everything from `code/`

All scripts in `code/` must be launched with `code/` as the current directory, **never** from the repo root:

- The `*_utils/` packages are imported via local relative-style imports (e.g. `from search_utils.search_utils import ...`); these only resolve when CWD is `code/`.
- README command examples use `../data/...` paths, which are relative to `code/`.
- `chat.py` hardcodes its log output to `conversation.log` in CWD.

`scripts/build_knowledge.py` is the supported end-to-end corpus/graph driver. Launch it from the repository root (or by absolute path); it starts subprocesses with `code/` as CWD. It uses existing HTTP services only, separates served model aliases from local/HF tokenizer identifiers, discovers all news files, verifies checkpoints before resuming, and publishes a new backend bundle only after graph/Qdrant checks. Logs and the resumable cache live in the sibling `.<output-name>.build` directory. No local vLLM or torch is needed for its HTTP metadata stages. The old `index_kb.sh` is an author-specific legacy workflow.

`--source-url` optionally downloads the required prepared/raw inputs from a public Yandex Disk folder before source discovery. Download selection and SHA-256 checksums are pinned in `.yandex-source.json` inside `--input-dir`; complete files are reused, partial downloads remain `.part`, and existing differing local files are never overwritten. Without that flag, inputs must already exist. Dry-run never contacts Yandex, even when the input directory is absent.

The current indexing LLM is `gemma-4-12B-it` at `http://everest.nsu.ru:9022/v1`, separate from the dialogue Meno service. `load_hf_tokenizer` in `tokenization_utils` adapts Transformers 5 list-form `extra_special_tokens` (Gemma 4) to the pinned Transformers 4 CPU environment without editing files or changing token IDs. Use it for corpus and graph-build tokenizers. The driver infers the context from the selected served model's `max_model_len`, falling back to 16384 only when absent; an explicit value must fit the served window.

The driver supports `--log-level INFO|DEBUG` and forwards it as `--log_level` to the graph CLI. RAGU's upstream logger hardcodes INFO, so configure its sink explicitly in the graph entrypoint. Log verbosity does not affect resume fingerprints. Stage logs append timestamped attempts; the documented tmux command also tees all console output to a persistent full-run log.

## Code layout

`code/` is flat: standalone pipeline scripts plus a set of local packages (`*_utils/`, each a directory with `__init__.py` and one same-named module). The packages are:

- `search_utils` — chunk combining (`combine_relevant_chunks`); `load_dense_embedder`/`vectorize_texts` (local SentenceTransformer) and `DenseEmbedderService` (OpenAI-compatible embeddings service adapter with the same `encode()` interface) are used only by the step-7 scoring script
- `context_utils` — assembles retrieved chunks into the LLM context, global↔local chunk-index mapping, renders graph elements (entities/relations) into context blocks (`graph_element_to_text`, `prepare_graph_elements_context`) and formats source references
- `graph_utils` — RAGU graph search adapter: exact Menon-chunk ↔ RAGU-chunk id mapping (`menon_chunk_mapping.json`), engine loading (`load_graph_engines` — `EmbedderOpenAI` + fastembed BM25 sparse + optional `ScorerOpenAI` engine reranker + Qdrant storage, own event loop, sparse-wiring sanity checks; an empty `engine_reranker_name` string is treated as "no engine reranker"), `GraphSearchEngines.search` returning a mixed pool `{chunks: [(global_idx, score)], entities: [...], relations: [...]}` with per-source normalized scores and `sources` mapped to global chunk indices, `find_relevant_items_by_graph`, `collect_knowledge_base_chunks` with optional contextual enrichment (`enrich_chunk_text`, modes `none`/`title`/`title_annotation`; the header format is frozen because RAGU chunk ids are md5 hashes of the resulting texts), and `AbbreviationExpandingExtractor` (a `TwoStageArtifactsExtractorLLM` subclass adding a contextual abbreviation-expansion pre-stage — chunks are LLM-rewritten for extraction only while the KB keeps original texts and rewritten copies keep original chunk ids; skipped for chunks without dictionary candidates; a rewrite is accepted by a formal check: length bounds, Levenshtein distance within the occurrence-weighted expected expansion cost plus slack, and a Snowball-stemmed expansion trace, otherwise the original chunk is used) plus `canonicalize_artifacts` (unifies entity-name variants differing by case/punctuation/spacing/ё to the most frequent spelling with edge punctuation trimmed, remaps relation endpoints so downstream grouping merges the duplicates)
- `rerank_utils` — LLM-as-reranker (vLLM or OpenAI API); both rerank functions accept `extra_document_texts` (rendered graph elements) appended to the chunk-based documents
- `rewriting_utils` — query rewriting, abbreviation expansion
- `qa_utils` — final QA prompt + system prompt
- `filter_utils` — shared text-quality checks (`text_is_good`, `count_words`, `normalize_text`, `BAD_PHRASES`, `MIN_NUM_WORDS`) used by `combine_data.py` and `validate_base_urls.py`
- `dialogue_history_utils`, `inference_utils`, `tokenization_utils`, `vllm_utils`

Main entrypoints: `chat.py` (interactive REPL loop), `search_context_by_query.py` (batch retrieval test), `prepare_graph_index.py` (offline RAGU knowledge-graph build over the final corpus), `prepare_chunk_mapping.py` (builds `chunk_mapping_to_texts.json` over the final corpus), `show_graph_search.py` (single-query graph retrieval debug), `crawl_nsu_for_kb.py` (NSU site crawler producing the `-b` base file), `generate_title_and_annotation.py` / `evaluate_title_and_annotation.py` (metadata), `update_title_for_news.py` (news title enrichment), `show_*.py` (single-subsystem debugging). Automation helpers: `index_kb.sh` (full indexing driver; skip-if-exists steps, `FORCE=1` to override, auto-starts a local Qdrant docker container and the local embedder service, step logs in `../logs`), `serve_local_embedder.sh` (local vLLM bge-m3 embedding service on port 8001 — the embedder runs on the workstation GPU, not on the cluster; `VLLM_BIN` points to a stable vLLM env because the PATH one is a dev checkout), `open_tunnels.sh` (ssh tunnel to the Cascade Meno service on local port 8023), `slurm/` (sbatch job `meno-idx` for the Meno service; partition `a100` without a node pin but `--exclude=ngpu01,ngpu05,ngpu06` — the legacy CUDA 11.7/`vllm_env` nodes whose vLLM 0.7.3 engine died on guided decoding during indexing; the job lands on the first free CUDA 12.6/`actual_env` node; see README §3.14).

## Knowledge-base build is a strict 8-step pipeline

Each step consumes the previous step's output JSONL. See README §3 for exact commands. Order:

`prepare_nsu_main_info_corpus.py` → `prepare_teachers_corpus.py` → `combine_data.py` → `apply_chunking.py` → `calculate_num_tokens.py` → `generate_title_and_annotation.py` → `evaluate_title_and_annotation.py` → `histogram_of_document_scores.py`

The former steps 6–7 (`prepare_bm25_index.py`, `prepare_vector_index.py`) were removed on 2026-10-20: retrieval is graph-only, so the Faiss and bm25s indices are not built anymore. The reverse chunk index `chunk_mapping_to_texts.json`, formerly written by `prepare_bm25_index.py`, is now built by `prepare_chunk_mapping.py`; it must be built over the final corpus because `calculate_num_tokens.py` sorts documents by token count and later steps preserve that order.

Optional: `validate_base_urls.py` before `combine_data.py`, `update_title_for_news.py` after step 7, `prepare_chunk_mapping.py` after all corpus changes, `prepare_graph_index.py` after the whole pipeline (RAGU graph + Qdrant collections; needs served Meno LLM + served bge-m3; `--vector_only` needs neither).

Optional preprocessing before `combine_data.py`: `validate_base_urls.py` filters the `-b` base file by text quality and URL accessibility (parallel HTTP checks via `urllib3` with per-host connection limiting). Optional post-step-6/7 enrichment: `update_title_for_news.py` appends a human-readable publication date ("(новость опубликована …)") to `doc_title` of `content_source == 'news'` records; `-b` is the metadata JSONL, `-n` the news files (repeatable, same `*_yyyymmdd_yyyymmdd.jsonl` naming rule), `-o` the output; `--timezone` defaults to `Asia/Novosibirsk`, independent of system locale.

The `-m` model is **not** the same for every step: step 6 (`generate_title_and_annotation.py`) is a generative pass using the Meno LLM, but step 7 (`evaluate_title_and_annotation.py`) scores generated annotations via bge-m3 **embeddings** (the embeddings service with `--url`, or a local `SentenceTransformer` without it — not a decoder LLM either way). Don't assume every `-m` is a generative model. Steps 1–3 (`prepare_nsu_main_info_corpus.py`, `prepare_teachers_corpus.py`, `combine_data.py`) take no `-m` at all.

Final artifacts consumed at query time: `data/chunked_texts_about_nsu_with_metadata_and_scores.jsonl` (corpus), `data/chunk_mapping_to_texts.json` (global chunk index → (doc, chunk-in-doc); built by `prepare_chunk_mapping.py`), `data/knowledge/abbreviations.json`, and `data/knowledge/ragu_graph/` (RAGU graph + `menon_chunk_mapping.json`; vector collections live in Qdrant at the `--qdrant_location` used during the build).

## Models and paths

- **Embedder**: bge-m3 served by an OpenAI-compatible embeddings service (e.g. vLLM); wired through RAGU's `EmbedderOpenAI` (`-e/--embedder` flag = the model name as the service sees it, e.g. `BAAI/bge-m3`). A local `SentenceTransformer` copy (`/home/bond005/models/bge-m3`, 1024-dim, no query/passage prefixes) is used only by the step-7 scoring script in its local mode (without `--url`); with `--url` that script queries the embeddings service through `search_utils.DenseEmbedderService`. No instruction prefixes for queries or passages.
- **Sparse channel**: local fastembed `BM25(language='russian')` from RAGU (`ragu.models.sparse_embedder.BM25`); language is fixed in `graph_utils.SPARSE_MODEL_LANGUAGE`.
- **Engine reranker (first pass)**: bge-reranker-v2-m3 served by a vLLM/Infinity-style scoring API (`{base_url}score`), wired through RAGU's `ScorerOpenAI`. Two-pass reranking is the **default scheme**: `--engine_reranker` in `chat.py` and `search_context_by_query.py` defaults to `BAAI/bge-reranker-v2-m3`; an empty value (`--engine_reranker ""`) disables the first pass. `show_graph_search.py` keeps it optional.
- **Generative LLM / reranker (second pass)**: Meno variants, e.g. `bond005/meno-lite-0.1`, `bond005/meno-tiny-0.1`, or any Qwen/Gemma-style LLM (vLLM offline or an OpenAI-compatible API).
- **Vector storage**: Qdrant. **Full graphs (entities + relations) need either a Qdrant server or `:memory:` within a single process**: the local on-disk mode allows a single client per folder, so the three vector storages (nodes/edges/chunks) cannot coexist there. `--vector_only` builds work on-disk; `:memory:` is what the integration test uses. README §2.3 lists the server launch options (native binary or Docker).
- Scripts try the HF Hub ID first, then fall back to `os.path.normpath(...)` as a local path. README/commands reference local copies under `/home/bond005/models/...` — adjust these to your own model locations.

## Script quirks

- **`--vllm` flag** toggles between offline vLLM inference (requires CUDA, takes most of GPU via `--gpu` mem fraction) and an OpenAI-compatible API (`--url`, `--key`, default `http://localhost:8000/v1`, key `EMPTY`).
- All scripts that touch the network clear proxy env vars at the top (`HTTP_PROXY=''`, etc.) and set `TOKENIZERS_PARALLELISM=false`, `PYTORCH_ALLOC_CONF=expandable_segments:True`, `VLLM_WORKER_MULTIPROC_METHOD=spawn`.
- `combine_data.py`: `-s/--summary` (required, one file) feeds the curated handbook corpus with unconditional priority (no dedup, `content_source='summary'`); `-t/--teachers` (required, one file) is the JSONL produced by `prepare_teachers_corpus.py`; its records are written right after the summary ones, also unconditionally (`content_source='teachers'`, no dedup, no filtering, not added to the dedup index); `-n/--news` is `action='append'` (repeat the flag per file); news filenames **must** match `*_yyyymmdd_yyyymmdd.jsonl` or the script raises. News are sorted newest-first and deduped; `-b/--base` (required, one file, crawled site data) is deduped against news via word-overlap F1 ≥ 0.9 using an inverted index (a size-band prefilter skips candidates that cannot reach the F1 threshold; the base file is streamed, not fully loaded). Filtered-out records are not printed: the final statistics report the counts of empty, duplicated, and bad texts (the former `--silence` flag is gone).
- `prepare_teachers_corpus.py`: reads `data/source/teachers.json` (structured profiles + timetables) and `data/source/teachers_chunks.json` (pre-rendered self-contained markdown chunks, index-aligned with `teachers.json`; alignment is verified by the `# <Full Name>` header of each first chunk). Emits one JSONL record per chunk (`{"text", "url"}`, `url` = the teacher's timetable page). By default only teachers with a non-empty timetable are exported; `--include_empty_schedule` disables the filter.
- `validate_base_urls.py`: optional preprocessing step for `-b` (base/crawler JSONL). Three-phase filtering: (1) text quality via `filter_utils` (empty text, BAD_PHRASES, too short), (2) parallel HTTP URL checking (`urllib3.PoolManager` + `ThreadPoolExecutor`, auto-encodes non-ASCII URLs, per-host connection limiting, follows redirects, retries on timeout, tqdm progress bar), (3) drops records where ALL URLs are dead. CLI: `-i`, `-o`, `--concurrency` (500), `--timeout` (15s), `--retries` (1), `--max-per-host` (10). Dependencies: `urllib3`, `certifi`, `tqdm`.
- `prepare_nsu_main_info_corpus.py`: stdlib-only Markdown parser that turns `data/nsu_main_info.md` into the summary corpus JSONL fed to `combine_data.py -s`. Granularity = **one document per `##` section**, EXCEPT sections whose **number** (string) is listed in `SUBSECTION_LEVEL_SECTIONS` (currently `{'4'}` = «Институты и факультеты»), which are split per `###` into one document per faculty/institute. Prepends a self-contained NSU context header to every document, converts internal `###`/`####` to bold, renders each Markdown table row as a standalone human-language paragraph (column names + table title repeated per row, units expanded), and collects **all** unique in-section URLs per document into the `url` field (priority-sorted: `nsu.ru/n/…` > `education.nsu.ru/…` > PDFs). Short parent intros are merged into the first child. CLI: `-i/--input`, `-o/--output`, optional `--min_chars`/`--max_chars`.
- `crawl_nsu_for_kb.py`: async `crawl4ai` deep crawler over the NSU site (curated seed lists by topic + BFS deep crawl with domain/URL-pattern filters, `PruningContentFilter`, PDF download & text extraction via `pymupdf`). Writes `pages.jsonl` (the `-b` base file) and `summary.json` into `-o` (default `/tmp/opencode/nsu_crawl`); `--mode` ∈ {`curated`,`deep`,`all`}, plus `--deep_max_pages`, `--deep_time_budget`, `--pdf_budget`.
- **`url` field is polymorphic**: it may be a string (single source) OR a list of strings (document aggregates several web pages). All pipeline code normalizes via a `normalize_urls(value) -> List[str]` helper (defined in `context_utils.context_utils`, `combine_data.py`, `prepare_nsu_main_info_corpus.py`). `combine_data.py` dedups by a sorted-tuple key of normalized URLs; `context_utils.prepare_context` renders multi-URL references as `<n>. <title>` + each URL on its own line. The URL is **never** sent to the LLM (only `doc_title`/`doc_annotation` go into the prompt). Pass-through scripts (`apply_chunking.py`, `calculate_num_tokens.py`, `generate_title_and_annotation.py`) serialize the record verbatim and are agnostic to the URL type.
- `chat.py` opens its `-o` file in **append** mode and writes `conversation.log`. The REPL quits on input `<end>`, `<exit>`, or `<finish>`. The former few-shot in-context learning path (`--fewshots`/`--fewshots_emb`) was removed on 2026-10-19; the former Faiss/BM25 retrieval path was removed on 2026-10-20 (graph search is the only retrieval source now, `-g/--graph` is a required flag). `--engine_reranker` defaults to `BAAI/bge-reranker-v2-m3` (two-pass reranking is the default scheme); an empty value disables the first pass.
- Per rewritten query `chat.py` calls `find_relevant_items_by_graph` (local + naive RAGU modes, retrieval-only, no LLM calls), merges the pool, renders graph elements into document-like texts (`context_utils.graph_element_to_text`), and passes them to the LLM reranker via `rerank_documents_with_*`'s `extra_document_texts`. The final score blends the pool score (weight `1-alpha`) with the reranker score (weight `alpha`); kept items are split back into chunks and graph elements. The QA context is the DOCUMENT blocks plus a `**ЭЛЕМЕНТЫ ГРАФА ЗНАНИЙ**` block; references are document references with graph-element source documents deduped in.
- `chat.py` imports `graph_utils` lazily.
- `prepare_graph_index.py` reproduces the exact Menon chunk boundaries (chunk texts are fed as documents with `chunker=None`; RAGU hashes each chunk content into its id), saves the sidecar `menon_chunk_mapping.json` (RAGU chunk id → global chunk index) and supports `--vector_only` (naive-only graph, no LLM needed) and `--max_chunks` (smoke runs). Extraction requests are deterministic by default (`--temperature 0.0`) and length-capped (`--max_completion_tokens 4096`); `-a/--abbr` enables the chunk abbreviation-expansion pre-stage (`AbbreviationExpandingExtractor`, see `graph_utils`); the script fails when the built graph contains neither entities nor relations (dead-LLM-service guard). Degenerate chunks whose generation hits the completion ceiling (`LengthFinishReasonError`) get no artifacts — the chunk stays in the KB (naive search unaffected), a warning is logged, and the failed call is not cached. Optional contextual enrichment of the fed chunk texts: `--chunk_header` (`none`/`title`/`title_annotation`, default `none`) prepends a frozen document metadata header via `graph_utils.enrich_chunk_text`, `--chunk_header_sources` restricts it by `content_source` (recommended `base,news`); changing the header format invalidates all chunk ids and the LLM cache, i.e. a full rebuild. Dense vectors go through `EmbedderOpenAI` (`-e` + `--embedder_url`/`--embedder_key`); the sparse side is always fastembed BM25 with `sparse_type='bm25'` Qdrant collections. RAGU settings: `Settings.language='russian'`, `random_seed=42`, local tokenizer backends. The Qdrant location must match between the build and the query scripts (`--qdrant_location`).

## Data conventions (gitignored except committed artifacts)

- `data/source/` — raw crawled JSONL (input only), the generated summary corpus JSONL produced by `prepare_nsu_main_info_corpus.py` from `data/nsu_main_info.md`, plus the raw teacher JSON files (`teachers.json`, `teachers_chunks.json`) and the teacher corpus JSONL produced by `prepare_teachers_corpus.py`.
- `data/` — processed pipeline stages (`*.jsonl`) + `chunk_mapping_to_texts.json`.
- `data/knowledge/` — the RAGU graph (`ragu_graph/` + optional LLM cache directories) + `abbreviations.json`. Vector collections live in Qdrant, not on disk.
- `data/fewshots/` — judged dialogue datasets in `.json` (`fewshots_ru.json`, `mtrageval_ru.json`) plus `source/` with third-party retrieval-eval sets (`clapnq`, `cloud`, `fiqa`, `govt`, `mtrageval_dialogues`); kept as inert sample/eval data (the few-shot mechanism was removed on 2026-10-19); `mtrageval_ru.json` serves as a sample input for `show_dialogue_history.py` (README §5.1).
- `pictures/` — generated charts.
- Source records: base file uses `{"text","url"}`; news files use `{"content","url", ...}`; teacher corpus records use `{"text","url"}`. United output adds `content_source` ∈ {`summary`,`teachers`,`base`,`news`}.
