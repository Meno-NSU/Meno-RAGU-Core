# Граф и поиск RAGU-стенда: план v5 (12.11.2026)

Цель: граф, полезный для вопросов о НГУ и Академгородке, — без мусорных узлов и связей, с правильно слитыми
дублями, с типами, которые описывают этот домен, — и поиск, который приносит в промпт только нужное. Мерило —
наши бенчмарки (954 вопроса RAGAS, 558 с эталонными страницами) и покрытие информационного поля.

## Направления — по ожидаемой пользе для бенчмарка

### 1. Чистота контекста (стенд; быстро)
- Порог релевантности для фрагментов и элементов графа (оценка LLM-реранкера, как `v2_rerank_threshold` у
  Менона): брать до 12, но только выше порога; элементы графа — только выше порога, а не всегда 3.
- Подбор порога офлайн: один проход реранкера на 323 вопросах с эталонной страницей, отбор пересчитывается при
  разных порогах (как подбирали вес приоритета источников) — попадание эталона, число блоков, доля блоков с
  эталонных страниц. Затем RAGAS (context precision, answer correctness, faithfulness) на выборке, ночью.
- Повторы в описаниях элементов (одинаковые предложения при склейке) — убрать при показе в промпте.

### 2. Доменная онтология «nsu» поверх NEREL (сборка; ночь работы gemma)
RAGU берёт онтологию из YAML с подтипами (`parent`): подтип проходит все ограничения родителя, так что связи NEREL
продолжают работать, а сборка не ломается. Набросок:

- ORGANIZATION → UNIVERSITY, FACULTY (факультет/институт НГУ), DEPARTMENT (кафедра), LABORATORY,
  RESEARCH_INSTITUTE (институты СО РАН), SCHOOL (СУНЦ, школы), COMPANY, STUDENT_ORGANIZATION
- PRODUCT → DISCIPLINE (учебная дисциплина, курс), RESEARCH_FIELD (область науки), EDUCATIONAL_PROGRAM
  (направление, профиль, программа), SOFTWARE, MATERIAL (вещество, материал), DEVICE
- PROFESSION → POSITION (должность), ACADEMIC_DEGREE, ACADEMIC_TITLE, EDUCATION_LEVEL (бакалавриат,
  магистратура, аспирантура)
- WORK_OF_ART → PUBLICATION, PERIODICAL (журнал, серия), THESIS
- LAW → REGULATION (положение, приказ, правила НГУ), FEDERAL_LAW
- EVENT → CONFERENCE, OLYMPIAD (олимпиады, конкурсы), ENTRANCE_EXAM, ACADEMIC_EVENT
- FACILITY → BUILDING, DORMITORY, AUDITORIUM, CAMPUS
- AWARD → SCHOLARSHIP, GRANT

Доменные связи (там, где сейчас PRODUCES / PARTICIPANT_IN / UNFIT): TEACHES (человек → дисциплина/программа),
AUTHOR_OF (человек → публикация), SUPERVISES (научное руководство), HEAD_OF (руководит подразделением),
OFFERS_PROGRAM (подразделение → программа), PROGRAM_INCLUDES (программа → дисциплина), REQUIRES (программа →
экзамен/документ), PUBLISHED_IN (публикация → журнал), RESEARCHES (человек/лаборатория → область),
AFFILIATED_WITH (лаборатория ↔ институт СО РАН). Не нужные домену связи NEREL (CAUSE_OF_DEATH, CONVICTED_OF,
PENALIZED_AS, MEDICAL_CONDITION…) уходят в RELATED_TO с сохранением текста.

Применение без новой экстракции: gemma размечает подтипы существующих сущностей (≈ 255 тыс. из типов PRODUCT,
PROFESSION, ORGANIZATION, WORK_OF_ART, EVENT, LAW, IDEOLOGY, FACILITY; ~5 тыс. запросов) и доменные типы связей для
UNFIT и перегруженных типов (~700 тыс.; ~18 тыс. запросов, ночь), выборки проверяет qwen; разметка — входы очистки
06, граф v5 собирается из готовых этапов 01–05, как v4. Онтологию нужно согласовать до разметки.

### 3. Дубли — систематично (сборка)
- Канонические реестры домена: сотрудники (страница «Педагогический состав», в базе знаний с якорями по ФИО),
  подразделения НГУ, образовательные программы (карточки Менона), институты СО РАН. Сущности привязываются к
  записи реестра — люди и подразделения получают один узел на объект.
- Второй круг кандидатов: ближайшие соседи по векторам с порогом ниже 0,9, кросс-скриптовые пары (латиница ↔
  кириллица, инициалы ↔ полное имя), одинаковые имена с разным регистром. Сливается только то, что подтверждают
  обе модели (gemma и qwen), как в v4.
- Петли после слияний (связь «X — другое имя Y» между слитыми узлами; 5,7 тыс. в v4) — их текст переносится в
  описание узла, а не теряется.

### 4. Мусор — второй круг (сборка)
- Узлы-обобщения («человек», «животные» под 6–8 типами), склеенные имена («1.3 Физические науки 1.5.2 Биофизика»),
  журналы с типом ORGANIZATION, идентификаторы и e-mail как узлы — разметка с доменной подсказкой, две модели;
  мусор становится частью описания соседа (как значения), без потери текста.
- Связи-копии между одной парой узлов (11,8% пар имеют 2+ связи) — склейка, если тип и смысл совпадают.

### 5. Поиск по графу (стенд)
- Однофамильцы и соседи по написанию (Гудылин вместо Вожакова): сущности ищутся только по векторам — добавить
  лексический канал (BM25 по именам) и сверку ФИО.
- Публикации: 24% связей — библиография; на вопрос «кто такой X» граф отдаёт статьи. Решение после онтологии:
  AUTHOR_OF как отдельный тип, который поиск поднимает только для вопросов о публикациях.
- Сообщества: RAGU умеет кластеризацию Лейдена, их резюме и глобальный поиск (сейчас выключены). Проверить на
  обзорных вопросах («какие направления на физфаке») — резюме сообществ верхнего уровня; это сотни–тысячи
  запросов к gemma.

### 6. Покрытие (сборка; дорого)
39% эталонных страниц 558 вопросов есть в базе знаний v3.8, но не в корпусе графа (v3k добавляет их только в поиск по
фрагментам). Извлечь граф из официальных страниц и документов базы знаний (без постов) — оценить объём и время
gemma; это самый дорогой шаг.

## Как меряем
- Без судьи: попадание эталонной страницы (323 вопроса), число и доля нерелевантных блоков, различие элементов
  графа между версиями (`diff_graph_pools.py`), аудит графа (`graph_audit.py`).
- С судьёй (qwen ночью, gemma в это время недоступна): парное сравнение версий на одном коде и одних вопросах —
  только там, где выдача различается.

3. Реестры и второй круг дублей, мусор второго круга → в v5 или v6.
4. Лексический канал для сущностей, AUTHOR_OF, сообщества — после v5.
5. Покрытие — оценка объёма, затем решение.
