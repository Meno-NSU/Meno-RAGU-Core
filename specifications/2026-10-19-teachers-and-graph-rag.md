# Спецификация: персоналии НГУ и графовый RAG в базе знаний «Менона»

- Дата: 19 октября 2026 г.
- Статус: код готов и проверен на смоук-тестах; пересборка базы знаний и сборка графа знаний не выполнялись (шаг генерации метаданных и сборка графа требуют доступной генеративной модели через vLLM-сервер или внешний API). Изменения не закоммичены.

## 1. Цели

**Задача A. Персоналии и расписания в базе знаний.** Интегрировать в базу знаний системы «Менон» сведения о преподавателях и сотрудниках НГУ, ведущих занятия в текущем (осеннем) семестре (профили, должности, дисциплины, публикации), вместе с их расписаниями. В текущих исходных данных расписание непусто у всех 1811 записей, поэтому фильтр по наличию занятий ничего не отсеивает. Источники: `data/source/teachers.json` (структурированные данные: ФИО, `schedule_url`, расписание, `employee_info`, `portal_info` с публикациями) и `data/source/teachers_chunks.json` (предотрендованные самодостаточные Markdown-фрагменты, 24 823 шт., выровнены с первым файлом по индексам; первый фрагмент каждой записи начинается заголовком `# <ФИО>`).

**Задача B. Графовый RAG на базе RAGU.** Подключить поиск по графу знаний (фреймворк RAGU, режимы local и naive) к существующему конвейеру: переписанные «Меноном» запросы подаются в графовые движки, найденные фрагменты вливаются в общий пул кандидатов перед LLM-переранжированием. RAGU используется только как формирователь контекста (метод `search()`, без генерации ответов); `QueryPlanEngine` не применяется — переписывание вопросов остаётся за «Меноном».

**Задача C (сопутствующая). Актуализация справочника.** Сверить `data/nsu_main_info.md` с живым сайтом НГУ: персоналии руководства факультетов и институтов, кабинеты деканатов. Правила: без домыслов; при малейших сомнениях файл не менять; сиюминутные статусы (отпуска, командировки) не фиксировать.

## 2. Принятые проектные решения

1. Корпус преподавателей готовит отдельный скрипт (`prepare_teachers_corpus.py`), `combine_data.py -t` принимает готовый JSONL — по образцу пары «prepare_nsu_main_info_corpus.py → -s».
2. Один фрагмент из `teachers_chunks.json` = один документ базы знаний; `url` — ссылка на страницу расписания преподавателя (`schedule_url`).
3. По умолчанию экспортируются только преподаватели с непустым расписанием (флаг `--include_empty_schedule` отключает фильтр).
4. Записи о преподавателях пишутся сразу после сводного справочника и полностью безусловны: без дедубликации, без фильтрации по длине текста, без попадания в обратный индекс дубликатов; `content_source='teachers'`.
5. Переход с FRIDA на **bge-m3** во всех подсистемах поиска и оценки документов (векторный индекс, запросы, оценки метаданных, граф). Механизм few-shot (динамическая подстановка примеров диалога) удалён 19 октября 2026 г.: не оправдал себя и усложнял код; статические образцы в промпте переписывателя сохранены. Инструктивные префиксы (`search_query:`, `search_document:`, `categorize:`) удалены — bge-m3 в них не нуждается. Размерность вектора — 1024.
6. Граф строится по всему корпусу (источники `summary,teachers,news,base`, флаг `--sources`).
7. Экстрактор — `TwoStageArtifactsExtractorLLM` с генеративной моделью семейства Meno через OpenAI-совместимый API (модели ragu-lm не используются). Промпты RAGU — на русском (`Settings.language='russian'`), сущности типизируются по онтологии NEREL; офлайн-режим `--vllm` у сборки графа отсутствует (RAGU работает по HTTP).
8. Модель векторных представлений графа — локальная bge-m3 через адаптер `EmbedderBgeM3`.
9. Слияние выдачи: графовые фрагменты (local + naive) вливаются в общий пул кандидатов (`combine_relevant_chunks`) перед существующим LLM-переранжированием; отдельный блок графового контекста в промпте QA не вводится (возможное расширение).
10. Границы фрагментов графа точно повторяют фрагменты базы знаний: тексты фрагментов подаются в RAGU как документы (`chunker=None`), идентификатор фрагмента RAGU — md5 от содержимого; соответствие хранится в сайдкаре `menon_chunk_mapping.json` внутри каталога графа.
11. Хранилище графа — локальное (NetworkX + JsonKV + NanoVectorDB); Qdrant не используется.
12. Детерминированность: `random_seed=42`; токенизаторы RAGU — локальные (`Settings.tokenizer_*_backend='local'`), без обращения к tiktoken и HF Hub в рантайме.
13. Конвенция номеров кабинетов (записана в разделе 1 справочника): трёхзначные номера — главный корпус (ул. Пирогова, 2), если явно не указан КПА (ул. Пирогова, 3); четырёхзначные — новый корпус (учебный корпус № 1, ул. Пирогова, 1). Конвенция применяется, когда расположение не указано явно: записи вида «ректорат, каб. NNN» относятся к отдельной башне ректората на ул. Пирогова, 1 (соединена с новым корпусом крытыми переходами через второй этаж) и имеют собственную трёхзначную нумерацию.

## 5. Что осталось сделать

1. Пересобрать базу знаний (шаги 1–10 конвейера, README §2): справочник → преподаватели → объединение (`combine_data.py -s -t -b -n`) → разбиение на фрагменты → подсчёт токенов → BM25 → векторный индекс на bge-m3 (`faiss_bge_m3.index`) → метаданные (Meno) → оценки → гистограммы. Порог `--min_quality` подобрать заново под шкалу bge-m3 (старые оценки несопоставимы).
2. Собрать граф знаний: поднять vLLM-сервер Meno (локально или на кластере «Каскад», партиция a800), выполнить `prepare_graph_index.py` по полному корпусу (~300 тыс. фрагментов) с дисковым кэшем (`--cache`); расчёт длится часы/дни и возобновляем после перезапуска. Быстрая проверка интеграции — режим `--vector_only` (без LLM).
3. Прогнать `chat.py --graph` на живых вопросах; подобрать `--graph_top_k`; вклад источников виден в логах (векторный/BM25/граф local/граф naive).
4. A/B-сравнение качества ответов с графом и без; при необходимости — расширение: отдельный блок графового контекста (сущности, связи, саммари сообществ) в промпте QA.
5. Закоммитить изменения в git (сейчас всё только в рабочем каталоге, включая незакоммиченную правку `data/nsu_main_info.md`).

- Модели: bge-m3 (`BAAI/bge-m3` или локальная копия) и Meno (`bond005/meno-lite-0.2` или другая).
