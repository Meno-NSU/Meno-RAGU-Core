| настройка | что делает |
|---|---|
| `GRAPH_EXPANSION_CANDIDATES` (0), `GRAPH_EXPANSION_HUB_CHUNKS` (200) | сущности берут чанки и связи по очереди; связи сущности упорядочены по покрытию запроса; до N чанков на запрос приходят с одного шага по типизированным связям; соседи-хабы не раскрываются |

где фрагмент был кандидатом и не был оставлен: метка реранкера «релевантно» (≥ 0,75) — 13, «частично» — 12,

качество равное и фрагмент стоит сразу за чертой (места 12–14).

## Рекомендация

1. **`MAX_CONTEXT_CHUNKS` 12 → 16**: +11 фактов из 92 без потерь, на контроле +2 без потерь, доля постов почти
   та же (12,5% → 13,7%), текст контекста +33%. 14 чанков — половина эффекта (+6) при +17% текста. Перед
   включением проверить судьёй: метрика здесь — фрагмент среди оставленных чанков до бюджета символов промпта.
2. **Приоритет источника не снимать**: при 0 постов 21,6% вместо 12,5%, новостей 10,9% вместо 3,3% — это то, что
   настройка 17.11 убирала; 0,5 почти ничего не даёт (+2).
3. **Разнообразие документов** даёт столько же, сколько 14 чанков (+8), но с одной потерей и ростом доли постов
   до 17%; отдельной настройкой не делалось. Как добавка к 14 чанкам оно равно 16 чанкам без него.
4. **Расширение и связывание не включать**: в итоговый контекст не доходит ни один фрагмент, пул кросс-энкодера
   растёт в полтора раза. **Соседние фрагменты** — единственная из трёх с приростом (+2, со всеми тремя +4 из 40)
   и без потерь в контексте; имеет смысл проверить вместе с 16 чанками.
5. Остаются вне досягаемости отбора: 57 из 92 фактов, чьего фрагмента нет среди кандидатов, и 18 фактов, чей
   фрагмент реранкер оценил ниже «релевантно».
